# MZ-2000 CMU-800 BGMシステム README

MIDIから作った曲を、CMU-800（6音＋リズム）で鳴らす仕組みです。
Arduinoのテンポクロックを **EXINT割り込み**に入れると、BASICのループの重さに関係なく、一定のテンポで演奏できます。

- 動作確認した環境: MZ-2000実機、CMU-800、Arduino Nano、BASIC MZ-1Z001
- 演奏ルーチンと曲データの組み合わせは、エミュレータ上で動作を確認しています（演奏の出力が一致することを確認）。
- 実機で確認済みの項目: 割り込み演奏のテンポ、ゲームとの共存。
- 確認していない項目: 本書の「リロケート」の、実機での動作（エミュレータでは、2か所で一致を確認）。

### バージョンと「元に戻す」方法
| 版 | 演奏ルーチン | 変換ツール | 特徴 |
|---|---|---|---|
| v1 | `bgm_cmu800.asm` | `mid2bgm.py` | 曲データが大きい。BASICが `USR($A003)` を呼んで進める |

## 2. 仕組みの概要

```
Arduino D9 ──→ CMU-800 のテンポクロック入力（従来どおり）
Arduino D10 ─→ MZ-2000 拡張I/O の /EXINT（テンポクロック1周期ごとの短いLOWパルス）
MZ-2000 RESET(正論理) ─→ Arduino D12（リセットを検出して、EXINTを自動で止める）
```

- テンポクロックは、**24パルス/拍**です（周波数 = BPM ÷ 2.5 Hz。120BPMなら48Hz）。
- /EXINTが入ると、Z80が0038Hに飛びます（IM 1）。0038Hを、演奏ルーチンの割り込み処理に書き換えてあります。
- 割り込み処理は、`BGM_TICK` を1回呼ぶだけです。`BGM_SPEED` 回の割り込みで、曲が1ステップ進みます。

## 3. メモリの使い方と制約

### 演奏ルーチンが使う領域
| 領域 | 内容 |
|---|---|
| `BGM_START`〜`BGM_START+37AH` | コードと音階表、デモ曲（約890 bytes） |
| `BGM_WORK`〜`BGM_WORK+9FH` | 作業領域（約20 bytes）と、**専用スタック**（128 bytes） |
| 曲データ | 任意の領域（後述） |

### 守ること
1. **割り込み方式では、演奏ルーチンも曲データも、C000H未満に置く。** 画面（GRAM）に切り替わっている間は、C000H以降が読めず、その間に割り込みが入ると、データを読み違えます。
2. **FE00H以降は使わない。** スタックなど、システムが使っています（実測: SP=FEEAH）。
3. D000H〜D7FFHは、画面の文字用メモリになる場合があるので、避ける。
4. 自分の使っている他のプログラムやデータと、重ならないようにする。

## 4. アセンブルとリロケート

### 4.1 アセンブル
AILZ80ASMで、`bgm_cmu800_v2int.asm` をアセンブルします。MZTにする時は、**実行アドレスを0000にしてください**（先頭アドレスにすると暴走します）。

### 4.2 置き場所を変える（リロケート）
ファイルの先頭にある、2つの定数を書き換えるだけです。

```
BGM_START   EQU 0A000H      ; 演奏ルーチンの先頭アドレス
BGM_WORK    EQU 0A500H      ; 作業領域＋スタックの先頭アドレス
```

守る条件:

| 条件 | 理由 |
|---|---|
| `BGM_WORK` は **256バイト境界**（下位バイトが00H）にする | 作業領域の計算が、1ページ内の前提のため |
| `BGM_START + 37AH` が `BGM_WORK` より小さい | コードと作業領域が重ならないように |
| どちらも **C000H未満**（割り込み方式の場合） | 3章の制約1 |
| `BGM_WORK` から `+9FH` までを、他に使わない | 専用スタックのため |

置き場所を変えると、**BASICから呼ぶアドレスが変わります。** `BGM_START` からの相対位置は、次のとおりです。

| 呼び出し | `BGM_START` からのオフセット | 既定（A000H）のアドレス |
|---|---|---|
| 初期化 `BGM_INIT` | +0 | `$A000` |
| 1ステップ進める `BGM_TICK`（割り込みでは不要） | +3 | `$A003` |
| 停止 `BGM_STOP` | +6 | `$A006` |
| 演奏開始 `BGM_PLAY` | +9 | `$A009` |
| テンポ設定 `BGM_SPEED`（POKE用の1バイト） | +0CH | `$A00C` |
| 曲の先頭アドレス `BGM_SONGPTR`（POKE用の2バイト） | +0DH, +0EH | `$A00D`, `$A00E` |
| CH8にCV=0を送る `BGM_CH8` | +0FH | `$A00F` |
| 割り込み演奏の開始 `BGM_INTON` | +12H | `$A012` |
| 割り込み演奏の終了 `BGM_INTOFF` | +15H | `$A015` |

実際のアドレスは、アセンブル後のリスト（`.lst`）でも確認できます。

### 4.3 曲データはリロケートできない
曲データの中には、領域をまたぐ所とループする所に、**絶対アドレスのジャンプ**が入っています。置き場所を変える時は、`mid2bgm2.py` の `--regions` を変えて、**データを作り直してください**（5章）。

### 4.4 サイズを減らしたい時
`SONG_DEMO`（デモ曲、約30 bytes）は、消してサイズを減らせます。その場合は、ソースの `BGM_SONGPTR: DEFW SONG_DEMO` を `DEFW 0` に変えてください。どちらの場合も、**BASICから必ず、曲の先頭アドレスをPOKEしてください**。

## 5. 曲データの作り方

### 5.1 MIDIの準備
- **MIDIチャンネル1〜6 → CMU-800のCH1〜6**に、そのまま割り当てるのが、いちばん簡単です（`--direct`）。1つのチャンネルは、**同時に1音だけ**（単音）にしてください。
- **チャンネル10（ドラム）→ リズム**（BD、SD、LT、HT、CY、OH、CH の7種類）。ドラムは、複数のトラックに分かれていても、チャンネルが10なら、1つにまとまります。
- CH7、CH8は、外部機器の出力用で、CMU-800本体には音源がありません。鳴りません。
- チャンネルごとに音を分けていないMIDIは、役割で割り当てます（5.4）。

### 5.2 基本のコマンド
```
python mid2bgm2.py 曲.mid -o 出力名 --direct --drums 9 --loop --loop-bar 8 --trim-lead --transpose -12 --regions A600-AFFF,B100-BFFF,9859-9FFF
```

| オプション | 意味 |
|---|---|
| `--direct` | MIDIチャンネル1〜6を、CMUのCH1〜6にそのまま割り当てる |
| `--voices 0,1,2,3,4,5` | `--direct` 時の割り当てを変える（0始まり。使わないボイスは -1） |
| `--drums 9` | ドラムのMIDIチャンネル（0始まりなので、チャンネル10は9） |
| `--drum-map 56=HT,82=CH` | ドラムの割り当てを追加・変更（BD, SD, LT, HT, CY, OH, CH, NONE） |
| `--res 8` | 1拍を何ステップに分けるか（既定8＝32分音符） |
| `--transpose -12` | 半音単位で移調（-12で、1オクターブ下げる） |
| `--start-bar` / `--end-bar` | 変換する範囲の小節（0始まり、`--end-bar` はその小節の手前まで） |
| `--origin` | 曲の開始位置のtick（最初の1拍だけ短い曲は480など。既定0） |
| `--trim-lead` | 曲頭の無音を削る |
| `--loop` | 最後まで行ったら、ループする（指定なしは、終了して止まる） |
| `--loop-bar 8` | ループで戻る小節（元のMIDIの小節番号。指定なしは先頭） |
| `--regions` | データを置く領域（16進、5.3で説明） |
| `--exec` | MZTヘッダの実行アドレス（既定0000。変えない） |

### 5.3 領域の指定

#### (a) 連続した領域が確保できる場合
領域を1つだけ指定します。**分割がなく、ジャンプ命令の分のデータも増えません。**
```
--regions A600-BFFF
```
出力は、1つのファイル（`出力名.mzt`）です。

#### (b) 飛び石にせざるを得ない場合
領域を、カンマで並べます。**途中に別のデータがある所を、避けられます。**
```
--regions A600-AFFF,B100-BFFF,9859-9FFF
```
- 先頭の領域から順に、詰めていきます。領域の終わりに、次の領域へのジャンプ（3 bytes）を、自動で入れます。
- 出力は、領域ごとのファイル（`出力名_A600.mzt`、`出力名_B100.mzt` …）です。**すべてロードしてください。**
- **先頭の領域のアドレスが、曲の先頭**です。ツールが、BASIC用のPOKEの値を、表示します。
- 入りきらない時は、足りない分を知らせて止まります。次のどれかで調整してください。
  - `--end-bar` を小さくする（曲を短くする）
  - 領域を足す
  - 5.5の目安を見る

#### 注意
`--regions` を指定しないと、`--base`（既定A600）から、メモリの上限まで、領域が続くとみなされます。**必ず `--regions` を指定してください。**

### 5.4 チャンネルが分かれていないMIDIの場合
`--direct` を付けずに、役割で指定します。
```
python mid2bgm2.py 曲.mid -o 出力名 --melody 0,1 --bass 2 --chords 3,4,5,7 --drums 9 --loop --regions ...
```
- メロディ（CH1）、ベース（CH2）、コード（CH3〜CH6、4音まで）に、まとめます。
- 同時に鳴る音が足りない時は、優先度の低い音を捨てます（捨てた数が、表示されます）。

### 5.5 データ量の目安
- 密な曲（Splash Wave）で、**約83 bytes/小節**です（87小節で約7.2KB）。
- 密度は曲によります。ツールが表示するデータサイズを、見てください。

### 5.6 テンポと分解能
- 1ステップの長さ ＝ 60 ÷ BPM ÷ `--res`（秒）。160BPM、`--res 8` なら、約47msです。
- 割り込み方式では、`BGM_SPEED`（BASICの `POKE`）は、**24 ÷ `--res`**にします。

| `--res` | `BGM_SPEED` | 備考 |
|---|---|---|
| 4（16分音符） | 6 | 32分音符がある曲には使えない |
| **8（32分音符）** | **3** | 既定 |
| 12 | 2 | 3連符の曲 |
| 24 | 1 | |

**24で割り切れない `--res`（5、7など）は、割り込み方式では使えません。**

### 5.7 音の切れ目（GT）について
CMU-800は、ゲートを入れたままだと、音が減衰して、聞こえなくなります。そのため、次の音との間に、**1ステップ以上の隙間**が必要です（GTは、次の音までのステップ数より小さくする）。
- ツールは、自動で、GT＝次の音までの長さ－1にします。
- **次の音が1ステップ後の箇所**（32分音符の連続など）は、隙間を作れないため、表示（「注意: …」）が出ます。音が弱くなる場合は、`--res` を大きくしてください。

### 5.8 複数の曲を入れる
曲ごとに、別々の領域で作ります（領域が重ならないように）。BASICで、`BGM_SONGPTR` を切り替えて、`BGM_PLAY` を呼ぶと、曲が切り替わります。

## 6. BASICでの使い方

### 6.1 割り込み方式（標準）
**プログラムの最初に、1回だけ**準備します。
```
USR($A000)                         ' 初期化(CMU-800を無音に)
USR($A012)                         ' 割り込み演奏の準備(0038H設置、IM 1、EI)
```

**曲を始める時**（ゲームのレース開始など）:
```
POKE $A00D,0:POKE $A00E,166        ' 曲の先頭アドレス(A600H)の下位、上位
POKE $A00C,3                       ' 3回の割り込みで1ステップ(--res 8の場合)
USR($A009)                         ' 演奏開始
```

**曲を止める時**: `USR($A006)`

**曲を切り替える時**: 新しい曲の先頭アドレスをPOKEして、`USR($A009)` を呼び直します。

**注意**: 割り込み演奏の間は、**`USR($A003)` を呼ばないでください**（二重に進みます）。

### 6.2 Arduino側の操作（シリアルモニタ、115200bps）
| 入力 | 動作 |
|---|---|
| `160` などの数字 | BPMを変更（曲の元のテンポに合わせる） |
| `E1`（または `ON`） | EXINTを出し始める |
| `E0`（または `OFF`） | EXINTを止める |

### 6.3 安全な運用ルール（重要）
- **起動の順番**: MZを起動 → BASICで `USR($A012)` → Arduinoで `E1`。
  **`E1` を先に入れると、MZが暴走します。**
- **終わる時**: Arduinoで `E0` → BASICで `USR($A015)`。
  **EXINTが出ている間に `USR($A015)` を実行すると、暴走します。** 通常は、**`USR($A015)` を呼ばず、`USR($A012)` を入れたままにして、曲は `USR($A006)` で止める**のが安全です。
- **MZをリセットすると**、ArduinoがRESETを検出して、自動的にEXINTを止めます。リセット後に、もう一度、`USR($A012)`、`E1` の順で操作してください。
- **EmuZ-2200（エミュレータ）では**、外から割り込みを入れられないので、確認は実機で行います。エミュレータでは、6.4のポーリング方式を使います。

### 6.4 割り込みを使わない方式（ポーリング）
ハードなしで使えます。ゲームのループの中で、`USR($A003)` を、1周に何回か呼びます。
- `BGM_SPEED`（`$A00C`）は、「`USR($A003)` を何回呼んだら、1ステップ進むか」です（1〜255。0は設定しない）。
- **呼ぶ間隔が不揃いだと、テンポがばらつきます。**
- この方式では、曲データを、C000H以降に置いても動きます。

### 6.5 CH8にCV=0を送る
`USR($A00F)` で、CH8に、CV=0のノートONを、1回だけ送ります（ATP3011の音声の起動に使っています）。曲の演奏とは、無関係に使えます。

## 7. Arduino側

### 7.1 配線
| Arduino | つなぐ先 | 備考 |
|---|---|---|
| D9 | CMU-800のテンポクロック入力 | 従来どおり |
| **D10** | MZ-1U01の **/EXINT** | **330Ω程度の抵抗を入れる**。HIGHは出さない（LOWか、ハイインピーダンス） |
| **D12** | MZの **RESET**（正論理） | **/EXRESET は使わない**（MZに入る信号で、LOWにするとMZがリセットされる） |
| GND | MZのGND | 共通 |

- /EXINTは、**LOWで割り込み、プルアップあり**です。
- EXINTのパルスは、約15µsです。もし、1回のパルスで、割り込みが2回入るようなら、スケッチの `EXINT_PULSE_TICKS` を3から2に下げてください。

### 7.2 起動時の動作
- **EXINTは、起動時はOFFです。** MZのIPLが始まらなくなるのを防ぐためです。

## 8. 既知の制限と対策

| 現象 | 原因（推定を含む） | 対策 |
|---|---|---|
| FOR〜NEXTで爆発音を鳴らしている間、BGMが遅れる | BASIC内蔵のビープ（`USR(3860)`）が、割り込みを禁止している可能性がある。EXINTは、要求を保持しないので、禁止中に来たパルスを取りこぼす | 爆発音を短くする、BGM中は使わない。ハードで要求を保持する回路（74HC74など）を足す案もある |
| ソフトで作る効果音（C000H）の最中に、割り込みが入る | 効果音は、ソフトで音程を作っているため | 今回の実機では、問題なし。気になる時は、効果音の前後だけ、割り込みを禁止する |
| ゲームがリセットされるとBGMが止まる | RESETで、EXINTを止める仕様 | リセット後に、手順をやり直す |
| 1つのチャンネルで、和音が鳴らない | CMU-800は、1ボイス1音 | MIDIを、単音に分ける |

## 9. トラブルシューティング

| 症状 | 確認すること |
|---|---|
| 音が鳴らない | `USR($A000)` を呼んだか／曲データを、すべてロードしたか／`POKE $A00D,$A00E` が、先頭アドレスか／`USR($A009)` を呼んだか／`BGM_SPEED` が0でないか |
| `E1` で、MZが暴走する | `USR($A012)` の後に、`E1` を入れたか |
| MZのIPLが始まらない | Arduinoが `E1` の状態か（起動時はOFFのはず）。スケッチが古くないか |
| テンポが、BPMと合わない | `BGM_SPEED` が、24÷`--res` か／BPMの値 |
| 割り込みが2回ずつ入る | `EXINT_PULSE_TICKS` を2に下げる |
| 音が弱い、すぐ消える | 5.7（GT）。次の音が1ステップ後の箇所が多い |
| ロード中にハングする | MZTの実行アドレスが0000か／領域が、システムの領域（FE00H以降）と重なっていないか |
| ドラムが鳴らない／違う音 | `--drums` のチャンネル番号（0始まり）、`--drum-map` |

## 10. 曲データの形式（v2）

1ステップの出来事を、1つの記録にまとめます。

```
[ヘッダ][次の記録までのステップ数][音階,GT]×発音数 [リズム]
```

| ヘッダ | 意味 |
|---|---|
| bit0〜5 | そのステップで発音するボイス（CH1〜CH6） |
| bit6 | リズムが付く |
| `00H` | 発音もリズムもない（待つだけ） |
| `FEH`, lo, hi | ジャンプ（領域をまたぐ時、ループする時） |
| `FFH` | 終了 |

- 音階とGTは、ヘッダのビットの小さい順（CH1から）に並びます。リズムは、最後に1バイトです。
- 音階は、0＝O0のC、1増えるごとに半音（MIDIノート番号 － 12 ＋ 移調）。範囲は0〜112です。
- GT（音を出す長さ）は、ステップ数（1〜255）。0は使いません。
- リズムのビット: bit7＝BD、bit6＝SD、bit5＝LT、bit4＝HT、bit3＝CY、bit2＝OH、bit1＝CH。
- 待ちが255ステップを超える時は、ヘッダ `00H` の記録を、続けて並べます。
